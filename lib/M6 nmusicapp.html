📘 Leçon 6.1 · Modèle Playlist

6.1.1 – Créer playlist.dart
Logique Globale :

Une playlist est un ensemble de chansons regroupées par l'utilisateur. C'est un concept métier central : Spotify, Deezer, Apple Music en ont tous. On crée une classe Playlist dans models/ pour représenter cette entité.

Une playlist doit avoir un identifiant unique, un nom, et contenir une liste de chansons.

Logique Syntaxe :
  • lib/models/playlist.dart : chemin du fichier.
  • Pourquoi dans models/ ? Parce que c'est une structure de données, comme Song.
Méthode :
  1. Dans VS Code, clic droit sur lib/models/.
  2. Nouveau fichier → playlist.dart.
📌 Contexte d'insertion : lib/models/playlist.dart.
✓ Checkpoint : Le fichier est créé.
6.1.2 – Déclarer la classe Playlist
Logique Globale :

On déclare la classe Playlist avec ses propriétés. Elle est immuable comme les autres modèles : une fois créée, on ne modifie pas ses propriétés, on crée une nouvelle instance si nécessaire.

Logique Syntaxe :
  • class Playlist { } : déclaration en PascalCase.
  • Pourquoi PascalCase ? Convention Dart pour les classes.
Méthode :
  1. Dans playlist.dart, importe song.dart (car la playlist va contenir des Song).
  2. Déclare la classe Playlist.
📌 Contexte d'insertion : playlist.dart.
// playlist.dart import 'song.dart'; class Playlist { }
✓ Checkpoint : La classe est déclarée.
6.1.3 – Ajouter les propriétés
Logique Globale :

Une playlist possède 3 propriétés essentielles :

  • id : identifiant unique (pour éviter les doublons).
  • nom : nom de la playlist (ex: "Ma playlist d'été").
  • songs : liste des chansons de la playlist.
Logique Syntaxe :
  • final String id; : identifiant unique.
  • final String nom; : nom de la playlist.
  • final List<Song> songs; : liste typée de chansons.
  • Pourquoi final partout ? Pour l'immuabilité. La playlist ne change pas après création. Si on veut ajouter une chanson, on recrée une playlist (ou on modifie la liste si elle n'est pas final dans sa référence).
  • Pourquoi List<Song> et pas List ? Pour la sécurité de typage. On ne peut y ajouter que des Song.
💡 Justification : On utilise final sur la liste pour la référence, mais le contenu peut être modifié. Si on voulait une liste totalement figée, on utiliserait const, ce qui n'est pas pratique ici.
Méthode :
  1. Ajoute les 3 propriétés dans la classe.
📌 Contexte d'insertion : playlist.dart.
// playlist.dart class Playlist { final String id; final String nom; final List<Song> songs; }
✓ Checkpoint : Les 3 propriétés sont ajoutées.
6.1.4 – Ajouter le constructeur
Logique Globale :

Comme pour Song, on ajoute un constructeur avec des paramètres nommés requis.

Logique Syntaxe :
  • Playlist({ required this.id, ... }) : constructeur avec paramètres nommés.
  • required : oblige à fournir chaque valeur.
  • this.songs : affecte directement le paramètre à la propriété.
Méthode :
  1. Ajoute le constructeur sous les propriétés.
📌 Contexte d'insertion : playlist.dart.
// playlist.dart class Playlist { final String id; final String nom; final List<Song> songs; Playlist({ required this.id, required this.nom, required this.songs, }); }
✓ Checkpoint : Le modèle Playlist est complet.

🔗 Point sur la cohérence entre les notions

📚 Détails et rétentions

  • List<Song> = liste typée.
  • final = immuable.
  • required = paramètre obligatoire.
  • PascalCase = classe.

6.2.3 – Implémenter createPlaylist()
Logique Globale :

On ajoute une méthode createPlaylist(String nom) qui crée une nouvelle playlist vide avec un nom donné.

Logique Syntaxe :
  • static void createPlaylist(String nom) : méthode statique.
  • DateTime.now().millisecondsSinceEpoch.toString() : génère un ID unique basé sur le timestamp actuel.
  • Pourquoi ce type d'ID ? Parce qu'il est unique à chaque milliseconde, sans avoir besoin d'un service externe.
  • Playlist(id: id, nom: nom, songs: []) : nouvelle playlist vide.
💡 Justification : On génère l'ID avec millisecondsSinceEpoch car c'est simple et fiable. Plus tard, Firebase générera ses propres IDs.
Méthode :
  1. Ajoute la méthode createPlaylist.
📌 Contexte d'insertion : playlists_manager.dart.
// playlists_manager.dart static void createPlaylist(String nom) { final id = DateTime.now().millisecondsSinceEpoch.toString(); playlists.add(Playlist(id: id, nom: nom, songs: [])); }
✓ Checkpoint : La méthode est implémentée.
6.2.4 – Implémenter addSongToPlaylist()
Logique Globale :

On ajoute une méthode pour ajouter une chanson à une playlist existante, identifiée par son id.

Logique Syntaxe :
  • static void addSongToPlaylist(String playlistId, Song song) : paramètres : ID de la playlist et chanson.
  • final index = playlists.indexWhere((p) => p.id == playlistId); : trouve l'index de la playlist.
  • if (index != -1) { ... } : vérifie que la playlist existe.
  • if (!playlist.songs.any((s) => s.id == song.id)) : vérifie que la chanson n'est pas déjà dans la playlist.
  • playlist.songs.add(song); : ajoute la chanson.
💡 Justification : La vérification anti-doublon est importante : on ne veut pas avoir deux fois la même chanson dans une playlist.
Méthode :
  1. Importe song.dart.
  2. Ajoute la méthode addSongToPlaylist.
📌 Contexte d'insertion : playlists_manager.dart.
// playlists_manager.dart import '../models/song.dart'; static void addSongToPlaylist(String playlistId, Song song) { final index = playlists.indexWhere((p) => p.id == playlistId); if (index != -1) { final playlist = playlists[index]; if (!playlist.songs.any((s) => s.id == song.id)) { playlist.songs.add(song); } } }
✓ Checkpoint : La méthode est implémentée.

6.3.5 – Dialogue de création

  • TextEditingController : contrôleur pour le champ.
  • AlertDialog(title: Text('Créer une playlist'), content: TextField(...), actions: [...]) : structure du dialogue.
  • actions: [TextButton(...), TextButton(...)] : boutons Annuler / Créer.
💡 Justification : On utilise un dialogue pour demander le nom sans changer de page. Plus rapide et plus fluide pour l'utilisateur.
Méthode :
  1. Dans onPressed, crée un TextEditingController.
  2. Appelle showDialog.
  3. Dans le dialogue, ajoute un TextField.
  4. Dans les actions, gère "Annuler" et "Créer".
  5. Au clic sur "Créer", appelle PlaylistsManager.createPlaylist, puis setState.
📌 Contexte d'insertion : playlists_page.dart.
